# Terratest harness

Go-based test suite that plans every OpenTofu module in this repository
against real AWS APIs. Run from this directory with `go test`, or via
`task test-plan` (plans, needs AWS creds) from the repo root.

Validate, disabled-path and negative-validation coverage formerly provided by
Go suites (`TestValidateAllModules`, `TestDisabledAllModules`,
`TestInvalidFixtures`) now comes from the creds-free offline `tofu test`
gate - see "Offline tests" below.

## Test suites

| Test | Needs AWS creds | What it proves |
|------|-----------------|----------------|
| `TestPlanAllModules` | Yes | Every module with `test/test.tfvars` plans successfully **and plans at least one resource** |
| `TestPlanFixtures` | Yes | Each optional `test/fixtures/plan-*.tfvars` plans successfully |

Common behavior:

- Module discovery walks the repo for `main.tf`, excluding `wrappers/`,
  `examples/`, `test/` and dot-directories.
- `TEST_MODULES=<mod1>,<mod2>` (comma-separated, paths relative to repo root)
  restricts any suite to specific modules.
- Plan-based suites skip locally when neither `AWS_DEFAULT_REGION` nor
  `AWS_REGION` is set, but **fail hard when `CI=true`** - in CI a missing AWS
  configuration means the OIDC credential step silently failed.

## Offline tests (`tofu test`)

Independent of this Go harness, every module carries a native OpenTofu test
file at `<module>/tests/offline.tftest.hcl`, generated by
`scripts/generate-offline-tests.py` and run with `task offline-test` from the
repo root (or `cd <module> && tofu init -backend=false && tofu test`).

**What it covers** - a creds-free plan of both code paths, on every PR, for
ALL modules:

- `run "plan_enabled"`: plans the module with the values from
  `test/test.tfvars`, with every required provider replaced by a
  `mock_provider` (no AWS credentials, no network calls).
- `run "plan_disabled"`: same variables plus `enabled = false`, proving the
  disabled path plans cleanly. Omitted for the pass-through `wrappers/`
  modules, which have no `enabled` variable (they get a minimal
  `plan_enabled` run with empty `items`).
- `run "invalid_<case>"`: hand-written negative tests proving variable
  validations fire - see "Negative testing" below.

**What it doesn't cover** - real API/provider behavior. Mocked providers
return fake computed values, so plan correctness against real AWS (IAM
semantics, computed attributes, quota/permission errors) remains the job of
the Terratest plan suite above.

Conventions:

- Generated runs are marked `do not edit by hand` - change the fixture or
  the generator and regenerate. Hand-written `run "invalid_*"` blocks (with
  their leading comments) are the one exception: the generator extracts and
  re-appends them verbatim on every regeneration.
- Every `mock_provider "aws"` block ships default `mock_data` for
  `aws_caller_identity`, `aws_region`, `aws_partition` and
  `aws_iam_policy_document`, whose computed attributes feed validated
  arguments across the repo.
- Where a mock-generated random string fails provider format validation
  (invalid ARN etc.), per-module `mock_resource`/`mock_data` defaults live in
  `scripts/offline-test-mocks/<module path, "/" replaced by "__">.hcl`. The
  generator's `--test --fix` mode derives most of these automatically from
  the plan error and iterates to a fixed point.

## Fixture conventions

All fixtures live inside the module directory, never in this `test/` harness
directory.

### 1. `test/test.tfvars` - default plan fixture

Realistic, complete variable values for the module's primary use case.
`TestPlanAllModules` plans every module that has one and asserts the plan
contains at least one resource change. An empty plan almost always means the
fixture left the module toggled off and is silently testing nothing.

Opt-out: if a module genuinely plans zero resources with its default fixture,
add an empty marker file `test/allow-empty-plan` next to `test.tfvars`.
(No module currently needs this.)

### 2. `test/fixtures/plan-<case>.tfvars` - additional plan paths

Optional. One file per extra plan path you want exercised (alternate feature
toggles, secondary resource shapes, ...). Each file must be a **complete,
standalone** variable set - it is passed to `tofu plan` as the only var file.
Subtests are named `<module>/plan-<case>`.

### 3. Negative testing - `run "invalid_<case>"` in `tests/offline.tftest.hcl`

Negative tests live in the module's offline test file, not in this Go
harness. Each one is a hand-written run block that MUST fail plan because
exactly one variable validation rejects it:

```hcl
# Hand-maintained negative test (preserved verbatim by generate-offline-tests.py).
# Must fail: name must be a non-empty string.
run "invalid_empty_name" {
  command = plan

  variables {
    name = ""
  }

  expect_failures = [
    var.name,
  ]
}
```

Rules for writing one:

- Name the run `invalid_<case>` - the generator preserves runs with this
  prefix (and their leading comments) verbatim when regenerating the file.
- `expect_failures` targets the variable whose `validation` block must fire.
  `tofu test` fails the run if that validation does NOT fail, or if anything
  else fails - so the run cannot pass vacuously.
- Include the module's normally-required happy-path variables so that **only**
  the targeted validation fails. Add a leading comment naming the validation
  being targeted.
- Verify locally:
  `cd <module> && tofu init -backend=false && tofu test`

No AWS credentials are needed: the offline tests mock every provider, and
variable validations are evaluated during plan expression evaluation anyway.

### Disabled-path testing (no fixture needed)

Disabled-path coverage lives in the offline tests, not in this Go harness:
every module's `tests/offline.tftest.hcl` includes a `run "plan_disabled"`
that plans the `test/test.tfvars` values with `enabled = false` against mock
providers, creds-free on every PR (see "Offline tests" above). This catches
the historical bug class where `enabled = false` breaks the plan (e.g. index
errors on empty resource collections).

## Running locally

```bash
cd test

# With AWS credentials (read-only; plan never creates resources)
go test -run 'TestPlanAllModules|TestPlanFixtures' -count=1 -timeout 60m

# Single module
TEST_MODULES=sns go test -run TestPlanAllModules -count=1 -v
```

For the creds-free offline tests (including the negative `invalid_*` runs):

```bash
task offline-test                                    # all modules
cd <module> && tofu init -backend=false && tofu test  # single module
```
